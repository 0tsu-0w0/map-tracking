# セキュリティ確認の結果(2026-11-21)

案A・案B の設定ファイル、API(`api/`)、地図画面(`web/`)、依存パッケージを見直した結果と対策。
位置情報は最も機微な個人情報の一つなので、「外から触れる所を減らす」「認証を破られにくくする」「サーバーを止められにくくする」を優先した。

## 見つけた問題と対策

重大度は、10 人程度で使うこの構成での影響で付けた。

| 重大度 | 問題 | 対策 |
| --- | --- | --- |
| 高 | パスワード検証(Argon2、1 回約 64 MiB)がイベントループ上で動いていた。ログイン試行が続くと位置の受信や配信が止まり、同時に大量に来ればメモリも使い切る | 別スレッドで動かし、同時実行を 2 つまでに制限 |
| 中 | 認証失敗の制限が接続元 IP ごとだけで、多数の IP から 1 人を狙う総当たりを止められない。記録も消えずに増え続けた | 利用者名ごとにも数える。記録数に上限を設け、期限切れを掃除 |
| 中 | OwnTracks の HTTP モードは位置ごとに Basic 認証するため、そのたびに Argon2 が走る | 確かめた認証情報を 10 分だけ覚える(パスワードは持たず、ランダム鍵の HMAC だけ)。パスワードを変えると無効 |
| 中 | 遅いブラウザがあると、WebSocket の送信待ちで位置の受信処理まで遅れる | 相手ごとのキューで送り、あふれた相手は切断。1 人 10 接続まで、受信は 64 KB まで |
| 中 | 端末名に日本語があると書き出しのファイル名ヘッダーで 500 エラーになる | RFC 5987(`filename*=UTF-8''…`)で渡す |
| 中 | CSV 書き出しで、端末から届いた文字列が `=` などで始まると表計算ソフトで数式として動く(CSV インジェクション) | 先頭に `'` を付ける |
| 低 | 書き出しは DB 接続を握ったまま流すため、同時に大量に要求されると接続プールが尽きる | 同時 3 本まで(それ以上は 429) |
| 低 | API の応答(位置情報)がブラウザや途中のキャッシュに残りうる | `/api/` に `Cache-Control: no-store` |
| 低 | 画面に CSP がなく、万一 XSS があったときに被害を抑えられない | Caddy で CSP・`Permissions-Policy` を付ける(スクリプトは自サイトのみ) |
| 低 | 大きな本文・パケットで資源を使わせられる | Caddy で本文 1 MB まで、API の HTTP 受信は 64 KB まで、Mosquitto は `max_packet_size 262144` |
| 低 | バックアップ(DB の全データ)がほかのユーザーにも読めるファイル権限で作られる | `umask 077` で作る |
| 低 | 案A で `ACME_EMAIL` が空だと Caddy が起動しない | 前回の修正で必須にした |
| 低 | CI の GITHUB_TOKEN の権限が既定のまま | `permissions: contents: read` |

## 確認して問題がなかった点

- 外部に公開するのは 80 / 443 だけ。Mosquitto・API・DB は Docker 内部ネットワークのみ
- MQTT は匿名接続禁止、ACL で自分のトピックにだけ書ける。API・Recorder 用のアカウントは読み取りのみ
- SQL はすべてプレースホルダー。文字列を組み立てているのは定数部分だけ
- Web ログインは Argon2 + HttpOnly / Secure / SameSite=Lax の Cookie。トークンは DB に SHA-256 で保存
- 書き換え系の API は `X-Requested-With: fetch` ヘッダー必須(CSRF 対策)。WebSocket は Origin を確認
- 利用者名の有無を応答時間で推測されないよう、存在しない名前でもダミーのハッシュで検証する
- 見る権限のない端末は 404(存在を明かさない)。削除は本人か管理者だけ
- 画面は React のエスケープと `textContent` で表示しており、届いた文字列を HTML として扱う箇所はない
- API のコンテナは root 以外で動かし、`no-new-privileges` を付けた

## 残るリスク(運用で気をつけること)

- **管理者は全員の位置を見られる。** 管理者を増やすときは慎重に。
- **暗号化キーはサーバーの DB に平文で保存する**(復号に必要なため)。ブローカーからは読めなくなるが、サーバー管理者からは読める。
- **`.env` と `./backups` には秘密情報と全データが入る。** 権限を絞り、バックアップは暗号化して別の場所に置く。
- **`INITIAL_ADMIN_PASS`** はコンテナの環境変数に残る(`docker inspect` で見える)。初回起動後は `.env` から消して `docker compose up -d` し直す。
- **共有の追加画面で、利用者名が存在するかどうかは分かる。** 少人数の身内向けとして許容している。
- **Web のログインに 2 段階認証はない。** 長いパスワードを使う。必要になったら Authelia などを Caddy の前段に置く。
- **OS・Docker・イメージの更新**は自動ではない。月 1 回程度 `docker compose pull && docker compose up -d --build` する。
